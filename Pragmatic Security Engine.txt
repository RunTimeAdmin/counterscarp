# Pragmatic Security Engine (PSE)

> **A "Grown-Up" Smart Contract Security Suite.**
> No compliance fluff. No "Low Severity" noise. Just the tools you need to prevent draining.

## Overview

This engine is a modular security pipeline designed for Ethereum Virtual Machine (EVM) development. It aggregates static analysis, supply chain intelligence, fuzzing, and access control visualization into a single actionable report.

It is built to answer four questions:
1.  **Supply Chain:** Is my foundation rotten? (Vulnerable Dependencies)
2.  **Secrets:** Did I accidentally leak my keys? (Secrets Scanner)
3.  **Syntax:** Is my code patterns dangerous? (Static Analysis)
4.  **Logic:** Can a brute-force attack break my math? (Fuzzing)
5.  **Permissions:** Did I leave the backdoor open? (Access Matrix)

## 📁 Project Structure

```text
/security-engine/
├── orchestrator.py        # The Master CLI (Runs everything)
├── red_team_scan.py       # Wrapper for Slither (Filters noise)
├── supply_chain_check.py  # Checks OSV.dev for vulnerable libs
├── fuzz_wrapper.py        # Wrapper for Foundry (Parses attacks)
├── access_matrix.py       # Generates "God Mode" permission table
├── secrets_scan.py        # Pre-commit hook for private keys
└── README.md

```

## 🚀 Usage

### Option 1: The "Full Audit" (Recommended)

Run the Orchestrator to trigger the entire pipeline and generate a Markdown report.

```bash
# Basic Scan (Code + Dependencies + Permissions)
python3 orchestrator.py --target ./MyProject

# Full Scan (Includes Fuzzing - Requires a Test Contract)
python3 orchestrator.py --target ./MyProject --fuzz-contract InvariantTest

```

**Output:**

* Generates `ACTION_PLAN_YYYY-MM-DD.md` in your root folder.
* Contains a "Copy-Paste" remediation plan for every issue found.

---

### Option 2: Individual Modules

#### 1. Supply Chain Inspector

Checks your `package.json` against the Google OSV live vulnerability database.

```bash
python3 supply_chain_check.py ./MyProject/package.json

```

#### 2. Access Control Matrix ("God Mode")

Visualizes who can call what. Look for `🚨 PUBLIC` on critical functions.

```bash
python3 access_matrix.py ./MyProject/src/MyToken.sol

```

#### 3. Secrets Scanner

Run this before committing code to GitHub. Scans for Private Keys, API keys, and Mnemonics.

```bash
python3 secrets_scan.py ./MyProject

```

#### 4. Red Team Scanner (Slither Wrapper)

Runs Slither but filters out the "Informational" garbage. Shows only Medium/High risks.

```bash
python3 red_team_scan.py ./MyProject

```

## 🛠️ Configuration

### Tweaking the Fuzzer

Open `fuzz_wrapper.py` to change the intensity of the attack simulation.

```python
# Default is 1000. Increase to 10,000 for "Deep Audit" mode.
FUZZ_RUNS = 1000 

```

### Adding Vulnerability Definitions

Open `red_team_scan.py` to modify the `IGNORE_CHECKS` list if you want to silence specific Slither warnings (like `naming-convention`).

## ⚠️ Disclaimer

This tool is a **weaponized linter**. It is not a replacement for a human auditor. It is designed to catch the "stupid mistakes" so the human auditor can focus on complex architecture flaws.

**If the tool says "PASS," it does not mean "HACK-PROOF."**
